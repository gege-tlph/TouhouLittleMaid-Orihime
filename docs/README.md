# 开发文档入口（26.1.2 分支）

**本分支只放 26.1.2 的东西。** 1.21.11 的账本、审计与历史材料留在那条分支，
本目录不引用它们的路径——需要那边的结论时**复述结论**，不跨分支指路（隔离纪律见 `CLAUDE.md`）。

## 默认读取顺序

1. 根目录 `CLAUDE.md`：隔离纪律、工程纪律、证伪表与方法论（自 1.21.11 分支继承）。
2. [CURRENT_STATUS.md](CURRENT_STATUS.md)：当前事实与唯一待办来源。
3. [PORT_26X_AUDIT.md](PORT_26X_AUDIT.md)：要搬什么、搬得动吗、按什么顺序搬，以及测试搬运台账。

| 文件 | 唯一职责 | 何时读取 |
|---|---|---|
| [CURRENT_STATUS.md](CURRENT_STATUS.md) | 当前状态与待办 | 每次接手 |
| [HANDOFF.md](HANDOFF.md) | 分支、工作树与隔离约定 | 切换维护者或恢复现场 |
| [PORT_26X_AUDIT.md](PORT_26X_AUDIT.md) | **在建**：差异化全集、移植边界、完整性论证、测试台账 | 决定搬什么、核对有没有漏 |

状态只允许写入 `CURRENT_STATUS.md`。

## 维护预算

沿用 1.21.11 分支的规矩：**常驻入口合计不超过 1,000 行**，另允许至多一份在建设计文档
（当前是 `PORT_26X_AUDIT.md`，随移植完成或放弃移入 `docs/archive/`）。

- 写新段落前先问「这段取代了谁」，把被取代的删掉。
- 账本只写「现在什么是真的」；**会过时的数字一律不写**，改跑 `python docs/tools/facts.py`。
- 新增维护文档必须同时登记 `docs/tools/doc_lint.py` 的 `EXPECTED_DOCS` 与本表，否则门禁红。

## 工具

`docs/tools/` 是自 1.21.11 分支带入的**副本**，分支常量已改到本分支
（`release/26.1.2-clean` / `fork/port/26.1.2-fabric` / `mc26.1.2`）。
两边各自维护，**不做跨分支引用**。

| 工具 | 作用 |
|---|---|
| `release-gate.ps1` | 一条命令跑完全部机械门禁 |
| `doc_lint.py` | 死链、不存在的路径与提交、活跃文档份数 |
| `tree_equiv.py` | 忽略注释的内部/公开两树等价（**公开分支建立前不适用**） |
| `git_hygiene.py` | ref 命名、备份标签、跟踪完整性 |
| `facts.py` | 按需打印当前事实，不生成文件 |
| `cycle.ps1` / `mcp-up.ps1` | 专服 + 客户端自动化测试载体；**端口 8765/8766 全局唯一，不得与 1.21.11 分支同时起** |
